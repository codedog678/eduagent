# EduAgent 工程问题与修改过程

自 2026-10-27 起按用户要求持续记录：**遇到什么问题 → 什么原因造成 → 怎么解决 → 验证有什么效果**。新增能力补充“为什么加”和“加入后的效果”。已结束轮次只根据提交代码和运行档案补记；未留存的细分原因标为待查。

## 记录约定

每轮包含：日期/状态、问题或新增动机、原因及确认程度、实际解决方式、结果与未解决项、证据与版本。计划和建议不等于已实施，测试通过不等于真实任务成功。历史事实保留，新发现通过追加修正说明呈现。

## C01：增加双层长任务评测（历史补记）

日期：2026-10-26。状态：已完成。

1. **为什么加／遇到什么问题**：单轮问答和普通回归不足以证明多 Agent、事务、学生等待、跨会话与重启的完整长链路可靠性。
2. **原因**：确定性的安全合同与真实模型决策是不同层面，仅验证其中一层会遗漏另一层的问题。
3. **怎么解决**：增加 D01–D08 故障合同和 L01–L06 冻结真实场景，每例独立数据库，保存公开 Trace、状态、预算及费用；失败不重跑覆盖。
4. **效果**：确定性 8/8，首轮真实任务 0/6，37 次请求；验证了事务底座，也暴露预算、路由、委派错误与偏好采用缺口。

证据：[冻结设计](../evals/harness-long-task-design.md)、[首轮分析](../evals/harness-long-runs/20261026-deepseek-flash/analysis.md)。档案提交 `54b0f8e`，运行源码版本及摘要以该档案为准。

## C03：预算分层与专家最终结论（历史补记）

日期：2026-10-26。状态：工程修改已完成，真实效果部分改善。

1. **问题**：专家多轮工具调用消耗父预算，后续课程/Tutor 没有足够额度；L03 工具预算耗尽。
2. **原因**：局部工具循环与整条计划预算没有在执行前对齐，最终请求仍可能继续要求工具。
3. **怎么解决**：增加剩余链路与必要备题预算预检、动态专家额度、最后一次请求关闭工具、超额工具返回预算反馈；维持父边界。
4. **效果**：离线合同通过；修复后没有整体 exhausted，L05 跑通。局部工具跳过仍在 L01/L02/L06 出现，故不能宣称预算问题全部解决。

证据：[工程修复](../evals/harness-engineering-fixes.md)、[复测分析](../evals/harness-long-runs/20261027-deepseek-flash/analysis.md)，运行时提交 `d583a33`。

证据：[优化方案](../evals/harness-failure-analysis-20261027/optimization-plan.md)、[离线证据](../evals/harness-failure-analysis-20261027/evidence.json)。新增模型请求 0，提交 `026091a`。

## C09：缩小模型协议并让失败可定位

日期：2026-10-27。状态：代码已实现，针对性离线验证通过，真实效果待复测。

1. **问题**：模型需要生成完整 LearningPlan，专家 JSON 解析后才检查 findings、身份、角色动作等，错误被折叠。
2. **原因**：持久化模型与生成协议共用；原五次错误具体缺字段仍无法由旧档确认，不以本次机制测试反推。

4. **效果**：针对性测试确认缺 findings、缺问题、非法状态、非法动作、错身份、伪造来源能够分别定位；1/2 次可用模型额度分别失败/成功修正，未扩额度。真实成功率尚未测量。

代码：`python/core/specialist_drafts.py`、`coordination_models.py`、`specialist_runtime.py`；测试：`python/tests/test_harness_optimization.py`。

## C10：历史发现与事实快照

日期：2026-10-27。状态：代码已实现，针对性离线验证通过。

1. **问题**：已有历史因词法不匹配搜不到；规划输入不知道历史可访问；知识/画像重复查询消耗读原文额度。
2. **原因**：知识 ID 是过滤条件，原查询与原文措辞不一致；原提示没有前置、资料状态和历史候选快照。
3. **怎么解决**：增加通用错误/偏好/时态/词汇别名；无命中时每父运行最多一次同学生同知识点的有限发现。规划/专家接收候选摘要、知识前置/材料状态、画像和复习快照。摘要不计为全文读取；空查询仍为空；专家工具声明优先搜索/读原文，已提供快照的接口继续保留执行兼容。
4. **效果**：测试确认不跨学生/知识点、不将摘要计为已读、第二次不同无命中查询不再发现、空查询不浏览。通用“过去时态错误”能找到“误判…忽略”原文。否定句“不能声称偏好缺失”通过，明确“偏好缺失”仍拒绝。

代码：`learning_history.py`、`memory_retrieval.py`、`tool_executor.py`、`coordinator.py`。

## C11：保留有效发现并区分动作必要性

日期：2026-10-27。状态：代码已实现，针对性离线验证通过。

1. **问题**：备题门禁失败会擦除已验证 Curriculum 发现；模型可自行把建议升级为必要备题。
2. **原因**：专家发现与动作执行共用一个整体失败分支；预算检查依据模型步骤，而非原请求。
3. **怎么解决**：服务端保留原始请求，必要备题只由原请求/学生补充确定；给出前置快照并执行前预检，保留 409 前置错误码。可选动作失败保留 completed findings、限制和失败回执；必要动作失败保留发现但步骤失败、任务 partial，缺题添加明确检查项。Tutor采用时间/偏好约束，受助模式不承诺独立掌握度更新。
4. **效果**：测试确认可选略读备题失败仍交付安排，不生成违规题目；明确要求备题的同一路径保持 partial，已验证发现仍在。L05受助隔离与 D01–D08 的完整针对性回归通过。

## C12：离线验证发现兼容问题，修复后再测

## C13：完整回归暴露未加载图谱的兼容路径

日期：2026-10-27。状态：修复完成，重新验证中。

1. **问题**：完整回归出现 11 项失败（293 passed、2 skipped），集中在旧评测 fixture 构建和一个错误码合同。
2. **原因**：旧 fixture 的上下文没有加载知识图谱，新增快照直接访问 `None.nodes`；同时非法 extra 字段与缺 findings 并存时，被归为缺发现，掩盖一般 schema 错误。
3. **怎么解决**：未提供图谱时明确返回 `context_status=not_provided`、`practice_allowed=false`，不编造前置关系；非法动作单独归类，其余非法 extra 优先保留 schema 错误。审查同时补上规划 JSON 为数组/null 时的对象门禁，防止未捕获 AttributeError。
4. **效果**：上述兼容修复后完整回归 **304 passed、2 skipped**；新增数组/null 边界后再做最终回归留档。不跳过旧测试，不启动真实模型来验证 fixture。
