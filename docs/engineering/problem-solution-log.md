# EduAgent 工程问题与修改过程

自 2026-10-27 起按用户要求持续记录：**遇到什么问题 → 什么原因造成 → 怎么解决 → 验证有什么效果**。新增能力补充“为什么加”和“加入后的效果”。已结束轮次只根据提交代码和运行档案补记；未留存的细分原因标为待查。

## 记录约定

每轮包含：日期/状态、问题或新增动机、原因及确认程度、实际解决方式、结果与未解决项、证据与版本。计划和建议不等于已实施，测试通过不等于真实任务成功。历史事实保留，新发现通过追加修正说明呈现。

## C01：增加双层长任务评测（历史补记）

日期：2026-10-26。状态：已完成。

1. **为什么加／遇到什么问题**：单轮问答和普通回归不足以证明多 Agent、事务、学生等待、跨会话与重启的完整长链路可靠性。
2. **原因**：确定性的安全合同与真实模型决策是不同层面，仅验证其中一层会遗漏另一层的问题。
3. **怎么解决**：增加 D01–D08 故障合同和 L01–L06 冻结真实场景，每例独立数据库，保存公开 Trace、状态、预算及费用；失败不重跑覆盖。
4. **效果**：确定性 8/8，首轮真实任务 0/6，37 次请求；验证了事务底座，也暴露预算、路由、委派错误与偏好采用缺口。

证据：[冻结设计](../evals/harness-long-task-design.md)、[首轮分析](../evals/harness-long-runs/20261026-deepseek-flash/analysis.md)。档案提交 `54b0f8e`，运行源码版本及摘要以该档案为准。

## C02：修复正式运行前的报告空值中断（历史补记）

日期：2026-10-26。状态：已完成。

1. **问题**：确定性门禁后生成 Markdown 时发生中断，尚未发出模型请求。
2. **原因**：`live: null` 被当作字典读取。
3. **怎么解决**：显式兼容空值，增加相应回归，然后才开始正式真实运行。
4. **效果**：报告可以表达只有确定性结果的状态；零请求中断单独归档，没有混入正式模型结果。

证据：[首轮分析的运行事实](../evals/harness-long-runs/20261026-deepseek-flash/analysis.md)、[中断档案](../evals/harness-long-runs/20261026-deepseek-flash/prelive-interruption.json)。

## C03：预算分层与专家最终结论（历史补记）

日期：2026-10-26。状态：工程修改已完成，真实效果部分改善。

1. **问题**：专家多轮工具调用消耗父预算，后续课程/Tutor 没有足够额度；L03 工具预算耗尽。
2. **原因**：局部工具循环与整条计划预算没有在执行前对齐，最终请求仍可能继续要求工具。
3. **怎么解决**：增加剩余链路与必要备题预算预检、动态专家额度、最后一次请求关闭工具、超额工具返回预算反馈；维持父边界。
4. **效果**：离线合同通过；修复后没有整体 exhausted，L05 跑通。局部工具跳过仍在 L01/L02/L06 出现，故不能宣称预算问题全部解决。

证据：[工程修复](../evals/harness-engineering-fixes.md)、[复测分析](../evals/harness-long-runs/20261027-deepseek-flash/analysis.md)，运行时提交 `d583a33`。

## C04：委派失败码、跨会话接续与任务路由（历史补记）

日期：2026-10-26。状态：工程修改已完成，真实效果部分改善。

1. **问题**：内层失败被折叠；新 session 补充信息没有恢复计划；分散历史诊断请求误入 Tutor。
2. **原因**：工具边界不保留领域失败分类，路由先看文本意图而未优先处理已提交的待答状态。
3. **怎么解决**：透传稳定失败码与异常类型；同 learner/thread 的等待计划优先恢复，只有待答问题时接续 Tutor；扩展复合任务同义路由。
4. **效果**：L02 恢复同一 thread/plan 并关闭原问题，L03 正确进入 Coordinator。L02 业务仍 partial，专家具体字段错误仍被 `expert_result_invalid` 掩盖。

证据：[工程修复](../evals/harness-engineering-fixes.md)、[复测助手审计](../evals/harness-long-runs/20261027-deepseek-flash/agent-audit.json)，运行时提交 `d583a33`。

## C05：稳定记忆证据与偏好约束（历史补记）

日期：2026-10-26。状态：工程修改已完成，仍有校验与交付缺口。

1. **问题**：偏好已持久化且被检索，但计划仍声称没有偏好，学生可见安排未采用偏好。
2. **原因**：已提交记忆与模型计划缺少可检查的事实传递约束。
3. **怎么解决**：规划器和专家接收稳定画像；证据槽核验来源和缺失状态；冲突时回退到带真实约束的保守计划。
4. **效果**：L01/L04 偏好进入计划约束；L04 原话跨重启保留。但模型计划有证据冲突回退，最终回复未采用偏好，后续查到正则否定句误报路径。

证据：[工程修复](../evals/harness-engineering-fixes.md)、[补充分析](../evals/harness-failure-analysis-20261027/optimization-plan.md)。

## C06：修复后真实复测与评分口径发现

日期：2026-10-27。状态：评测与归档已完成。

1. **问题**：需要核实工程修复是否转化为完整真实任务成功。
2. **原因**：脚本模型能够验证边界，但不能保证真实模型满足结果契约。
3. **怎么解决**：用同一 6 条场景单次复测，保留原自动评分；另做助手离线审计，区分状态成功与业务交付。
4. **效果**：自动 0/6 → 2/6，只有 L05 确认工程闭环；L02 completed/partial 是业务成功假阳性。31 次请求，费用估算 0.07486088–0.14972176 元；请求减少但费用比首轮增加约 29.67%。

证据：[复测档案](../evals/harness-long-runs/20261027-deepseek-flash/)、[同口径指标对照](../evals/harness-long-runs/20261027-deepseek-flash/comparison-summary.json)。提交 `6fb4d24`。

## C07：用离线重放缩小原因范围

日期：2026-10-27。状态：原因核对已完成，生产修改尚未在此轮实施。

1. **问题**：L01 搜不到已有历史、L04 动作被通用拒绝码折叠，5 次专家校验错误无细分原因。
2. **原因**：L01 词法查询与原文不匹配，知识 ID 只是过滤条件；L04 请求略读备题但没有满足前置掌握。专家失败可定位到解析后检查，具体字段由于原模型载荷缺失仍待查。
3. **怎么解决**：按冻结虚构数据建立临时数据库重放查询和门禁；提取既有 Trace；补充 schema 与否定句诊断样例。
4. **效果**：确认 L01 原查询为空而原词查询可命中；L04 原动作触发 409 前置门禁；证据正则会误伤“不能声称偏好缺失”。不能据此认定原冲突就是正则误报，也不能断言 5 次专家都缺 findings。

证据：[优化方案](../evals/harness-failure-analysis-20261027/optimization-plan.md)、[离线证据](../evals/harness-failure-analysis-20261027/evidence.json)。新增模型请求 0，提交 `026091a`。

## C08：按已确认方案实施第二轮工程优化

日期：2026-10-27。状态：实施中。

1. **问题／新增动机**：消除已定位的协议落差、评分假阳性、资料发现阻断和不可行动作，并让后续失败能够准确复盘。用户新增要求是同步维护本记录。
2. **原因**：详见 C06–C07，已确认机制与待查原载荷分别保留；不把所有失败归为模型能力。
3. **怎么解决**：按[实施检查表](harness-optimization-20261027.md)推进草稿协议、细分错误、事实快照、受限资料发现、动作预检、预算内修正与评分版本化；每个实际修改完成后在下方追加独立记录。
4. **当前效果**：方案已获用户确认；代码与真实复测尚未完成，不能报告新的成功率。过程记录已创建，并补记以上有档案支持的历史轮次。
