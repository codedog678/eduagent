# Tutor 答疑约束修改与复测

**最终提示版本 `2026-10-25.3` 的 03、05、06 自动契约全部通过。** AI 复核显示：03 不再直接给出目标词；05 缺句时建立待答问题、补句后关闭待答；06 目标明确后直接提供阅读方法。

语义结论由本次执行助手提出，属于 **AI 辅助审阅**。原始报告中的语义项仍为 `review_pending`，人工评分尚未完成。

## 它与 Agent 评测的关系

这里评测的是教育 Tutor Agent 和 Harness 共同完成任务的行为：从学生输入和历史判断下一步，选择回答、澄清或检索，再提交对应的状态与学习证据。

| 任务 | 观察的 Agent 行为 | 成功依据 |
| --- | --- | --- |
| 找旧笔记中的口令（08） | 搜索历史，读取完整来源，再回答 | 指定原文、真实引用与工具路径一致 |
| 学生补充阅读目标（06） | 利用旧待答问题与新输入，决定信息是否充分 | 接续原问题，给定位方法，完成答复 |
| 处理受助与独立作答（11、12） | Tutor 提供帮助，Harness 与领域 Agent 记录评估 | 受助正确不更新独立掌握，新题独立首答才更新 |

03 的“只提示不代答”属于教育任务的回复约束，是辅助教学评测。状态断言还检验 Harness 的工程契约，不能单独作为模型能力成绩。本配置中的其他领域 Agent 使用本地策略协同；这是一组小规模教育 Agent 任务评测，尚未覆盖完整多 Agent 自主协作或通用 Agent 基准。

## 修改内容

| 位置 | 修改及作用 |
| --- | --- |
| `python/core/tutor_policy.py` | 集中定义通用答疑约束；未结束练习使用 `hint_only`，只给规则、检查点与判断步骤 |
| `ContextBuilder` | 将练习是否绑定、当前答疑模式与待答接续关系提供给模型；题目只公开题干、选项与知识点 |
| 澄清规则与工具说明 | 具体材料缺失时调用 `ask_student`；信息足够时先完成原请求，可选背景不阻断回答；学生明确要求问题引导时仍可提问 |
| Trace 与配置指纹 | 保存提示版本与答疑模式，区分修改前后的执行 |
| 回归测试 | 增加练习提示模式、题目结束后的公开讲解、跨会话接续、缺句补句及提示版本指纹验证 |

`hint_only` 允许说明“需要过去分词”等语法类别，讨论学生已提出的候选和公开词语。具体答案词形、完整填空句、直接词义答案与正确选项的最后判断留给学生。

## 最终版本的观察与 AI 复核

| 场景 | 实际观察 | 自动结果 | AI 语义建议 |
| --- | --- | --- | --- |
| 03 过去分词提示 | 明确 have 后需要过去分词，要求学生自行查证；没有提供 `written` 或推荐 B | 全部通过 | H4 可接受 |
| 05 缺句澄清接续 | 首轮单独 `ask_student` 索要原句；补句后 `answered_question_id` 对应原待答 ID，最终 answered；知识状态不变 | 全部通过 | H5 可接受；具体例句解释匹配，since 的一般化措辞仍可精简 |
| 06 阅读目标跨会话 | 两个 session 使用同一 thread；关闭原问题；给出关键词扫描、定位后精读与出发/到达验证，最终 answered | 全部通过 | H5 可接受；“通读是浪费”等绝对措辞仍可收敛 |

最终版 03 实际回复节选：

> 助动词 have 后面要求的是过去分词，而不是过去式。……你已确认过去式是 wrote，那么请再单独查一下 write 的过去分词形式是什么。

最终版 05 首轮实际提问：

> 请把你要分析的那句话（连同上下文，如果有的话）发给我，我需要看到原句才能判断它的时态。

最终版 06 第二轮实际行为：

> 明确了：这次是找具体细节（火车出发时间），不是主旨题。……扫读（scanning），不逐句读。……确认这个时间是“出发”而不是“到达”“检票”“换乘”。

v2 的相关场景 04、09、11、12 自动契约均通过：04 已明确区分提交物与接收者；09 继续拒绝恶意要求并解释时间关系；11 的受助正确仍不更新独立掌握；12 的新题独立正确仍只更新一次 BKT，mastery 为 `0.43333333333333335`。这些是 v2 观察，不拼接成最终版的全套通过率。
