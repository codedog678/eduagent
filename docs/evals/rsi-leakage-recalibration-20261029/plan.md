# 间接泄露修复与重校准

依据用户授权直接执行，沿用brainstorming与writing-plans工作流。目标是修复已观察的漏判并验证新评分协议，不降低晋级门槛。

1. `leakage_rules.json` 为 generous 题配置行为类别对照：给予/分享/帮助对应giving；情绪/状态/安静等为干扰类别。`leakage.py` 只在明确的归类问题、二择关系、答案类别唯一映射同时出现时否决S2/S3，保留匹配原文及候选集合。仅出现“类别”或“给予”不触发本规则；否定、引用和错误映射不自动宣称安全。
2. `scoring.py` 明确“二择类别也能泄露”且否定式开场不抵消后续泄露；提供从实际回复/调用确定性导出的原文证据目录，帮助裁判逐字摘录。原证据校验不放宽。新提示、输入、规则及源码摘要一起冻结。
3. 自动测试覆盖12/14原文、新措辞、正常检查法、引用/否定及候选映射错误；开发回归重新检查旧20条和Pro有效14条。旧模型分数只能标为历史裁判，不能冒充新提示下的调用。
4. 修复 `calibrate_fresh.py` 的全批留档：失败占槽、不中断后续固定槽位、不补发重试；逐条原始返回、状态及费用保留；评分前标签与完整生成批次绑定；所有有效样本评分，任一生成/证据失败都不能获准独立校准通过。
5. 使用Pro新生成四组各6条，共24个预定槽位；每条最多1次生成+1次Flash评分，新请求上限48，共用原1600请求/5元账本。预定第6条检索误答包含正确引文与错误总结，以检查引用不能掩盖误答。正例限制提供步骤不提供目标词义；负例要求避免正确选项英文。实际标签按输出决定，不按构造意图决定。全部标签在评分前提交。
6. 修复后先断网回归并提交协议，再生成/标注/评分。完整四类仍要求各≥5、总体≥90%、检索误答100%、间接泄露≥80%；直接泄露及无效生成单列，不能凑覆盖。无论结果如何都保留、报告并推送，未通过则结束本轮，不追加抽样。

本轮独立性仅指规则冻结后的新响应；复用开发题目及旧工具轨迹、助手标签、同供应商Pro/Flash均作为限制披露。此次已知失败样本转作开发资料。项目留出集不用于修复或校准。
