# 探索性 Campaign 执行协议

用户已明确授权降低试跑门槛，主要目标是启动探索、观察候选改善。沿用brainstorming/writing-plans流程，直接实施已确认方向。

- 增加不可变配置`mode=exploratory`；正式模式仍为`qualification`。探索入口允许当前真实校准报告：有效标签一致率≥85%、有效观测≥12、存在各能力组记录；不要求独立校准通过、误答100%命中或三次正式验收。失败和重复样本仍披露，旧报告不改写。
- 探索只复用现有TutorGEPAAdapter的执行、脱敏反思与提案器，采用两代有界反思搜索；不是调用GEPA标量优化循环。原因是裁判未知值不能伪装成0传给GEPA。
- 现有12条reflection_train任务：先评基线；每代从上一代训练结果中取最多3条最低分已知结果反思，提出新retrieval_rules，再评12条训练任务。验证结果不进入反思。候选2可以继承候选1进行探索，但不注册为正式合格父版本。
- 冻结14条开发任务×2次重复；基线和两个候选交错运行，首次重复基线先、次次候选先。每条每策略保存独立证据与未知状态。预计训练36次任务评估、开发84次任务评估、2次提案；请求最坏值运行前核对，共用原1600请求/5元预算。
- 裁判JSON/证据/覆盖失败在探索中记为unknown：score/task_success/decision_rate为null，不计成功或失败，不进入反思；任务工具硬约束失败仍是已知失败。API或共享预算故障保持停止语义。未知不触发无界重试，恢复复用已完成的未知观测。
- 输出每候选：完整配对数、未知配对数、wins/losses/ties、两次重复方向、能力组变化、自动检查退化、共同已知配对成功率和全样本成功率上下界。缺配对不删除；候选未知更多不能因此获得确定改善结论。
- 探索入口不能进入留出、Harness晋级、注册或发布；正式资格方法显式拒绝exploratory模式。探索候选只导出待复核策略。
- 修改文件：`adapter.py`、`campaign.py`；新增`exploratory.py`进行探索编排与描述性比较。CLI复用prepare/run，无新增授权流程。
- 断网测试验证：未知分数不能进GEPA/反思、成对统计未知边界、正式门禁不被放宽、探索无法晋级、完整恢复不重跑；使用统一断网入口。提交冻结代码、配置和协议后真实运行；保存全部结果、账本与C64日志，推送GitHub。
