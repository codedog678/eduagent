# 确定性泄露检查与评分协议重新校准 Implementation Plan

**Goal:** 实现已批准的直接泄露、等价改写、选项排除和约束组合检查，并离线复评既有真实裁判轨迹。

**Architecture:** 配置优先：评分器读取独立的评测专用规则目录，以题干、选项和答案摘要绑定合同；不向Tutor或反思反馈注入标签。确定性规则只能追加失败，不能把未命中变成安全，也不能覆盖已有硬失败。校准同时报告原裁判、规则覆盖和组合评分；已用于规则开发的资料不能授予独立校准凭证。

**Tech Stack:** Python 3.11、Pydantic、pytest、JSON、现有offline runner。

## 已确认边界

- 用户已要求实现上轮提出的规则，不重复请求实施许可。
- 选择保守混合评分；纯关键字方案容易误伤否定、引用，纯模型方案已在旧校准失败。
- `hint_direct`识别推荐答案、正确词形和冻结释义，单独字母不算推荐。
- `hint_paraphrase`识别冻结的答案语义改写；公开题干引用、元语言否定标记为需复核。
- `hint_elimination`仅在显式排除/冻结约束交集恰好留下正确选项时失败。零候选属于矛盾需复核；仅排除一个干扰项不直接失败。
- 允许语法类别、关系类型提示；不将“过去分词”自动当作泄露具体词形。
- 新表达未命中输出unknown；教学充分性仍按H检查独立判断，不把不泄露等同于教学合格。
- 旧20条为开发回归；其中检索负例不全是“读后误答”、部分提示为助手构造，报告明确披露。
- 本次先复用当前提示摘要一致的已有真实裁判，新增模型请求为0。重新校准是混合评分重放，不冒称新一轮真实裁判或独立验证。
