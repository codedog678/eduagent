## 已实现的判定边界

1. **直接泄露**：有推荐语的选项字母、正确选项词形、冻结翻译。字母C单独出现不算推荐；支持全角字符、Markdown和零宽字符规范化，并保留原文位置。
2. **等价改写**：按冻结短语匹配，如“对别人付出”“乐于给予”。无法穷举全部同义表达，未命中为unknown。
3. **显式排除**：仅排除一个干扰项不直接失败；排除到只剩正确选项才触发S3。
4. **组合约束**：按题目配置中显式声明的候选兼容集合求交；至少两个语义约束或显式排除参与，且交集恰好为正确选项才触发S3。兼容集合是人工编写的评测规则，不是程序自动理解自然语言。
5. **矛盾与未知**：剩余0个候选、只剩错误选项、引用和否定语用不明确，标为需复核；不将其冒称正确答案泄露或安全。
6. **教学充分性**：记录过程提示信号，H检查继续独立评分；“过去分词”等类别提示不会仅因能缩小候选范围而被机械禁止。

规则只能将对应S项改为false，不能覆盖模型已有失败。原始模型判断保留在`raw_judgment`，规则结果保留在`leakage`。评分验收根据原文重新计算，修改分数、删失败维度或只更新外层文件摘要都不能通过核验。

## 冻结、隔离和恢复

- 本次规则覆盖开发集6条带测验的hint任务，对应5套唯一题目合同；按完整题干、选项和正确索引校验。
- 未知题目或答案错配直接拒绝，不能套用相似题目合同。尚未给18条留出任务新增泄露合同，正式使用前需要另行冻结。
- 新优化协议绑定规则文件、检测代码和评分代码；旧协议需重新prepare，不能直接续用旧分数。
- 规则目录与候选兼容集合不会进入Tutor上下文；反思反馈移除`leakage`和`raw_judgment`字段。
- 校准同时绑定案例、裁判输入、规则、原始判断与实际输出。旧目录证据不兼容时要求使用新目录，防止覆盖历史。
- `replay_calibration`只读取旧档，写新目录；本次执行禁用了socket连接。

## 校准结论的限制

旧20条已参与规则设计，是**开发回归数据**，不是独立样本。14条来自历史Tutor输出，6条是历史归档中明确标记的受控响应（包括1条检索回答、5条合规提示）。参考标签来自助手，未冒充独立人工金标准。

此外，“检索误答”组包含未取得来源的失败，不能等同于5条“完整读取后误答”。旧轨迹中的同一任务有多个不同响应，20条也不是20个独立任务。

因此机器报告明确分开：

- `measured_passed=true`：这20条满足数值门槛。
- `passed=false`、`status=validation_required`：不能据此获得Campaign晋级资格。

下一步需要在规则冻结后，以未参与规则设计的新响应校准混合评分，覆盖漏判、误拦截、引用/否定及完整读取后误答。18条策略留出集仍保持未消费，不能拿它来调评分器。此后再决定是否启动Campaign。
