# 50 条 Agent 主任务扩展设计

依据已讨论的扩量方向和用户“扩大数据量到50条”的要求，目标是形成可执行、可按能力分组、事前定义评分标准的开发评测集。数据扩展本身不产生模型能力成绩。

保留原 8 条主任务原文，新增 42 条；原 4 条教学辅助仍在原 12 条文件中。覆盖分配为多轮接续 14、可见历史接续 8、全文检索 8、工具与缺失证据决策 6、注入及权限 8、学习证据 6。新增记录明确执行模板、主评测身份、能力、难度及每个答疑轮次的工具决策要求。

复用现有九种脚本契约和状态断言，以 `template_case_id` 连接新任务。知识点、学生输入、历史来源、完整检索原文和外部私有标记由配置提供；原 12 条仍按原标识解析。不增加工具、教学策略或掌握模型规则。未知模板、缺失变体元数据、错误脚本顺序和重复学习者均拒绝加载。

每条使用独立临时 SQLite，当前及外部学习者、历史消息、测验和会话标识隔离。评分标准、后续输入、答案索引与后续新题不提前进入模型上下文。全文检索先验证目标不在初始上下文、答案不在摘要、正文可完整读取；外部来源先验证当前学习者没有读取权限。

最终成功与工具选择、参数语义、漏调标准沿用既有评分口径，新条目运行前保存数据与评分文件摘要。此版本明确保存 `not_run_in_agent50` 和空评分；旧任务历史成绩仍留在旧报告中，不能混算。

新增 `validate-live` 使用评测器指定的工具动作与口令验证整套 Harness 链路；脚本知道预期答案，因此仅报告预置与契约是否可验证，模型成功和语义成绩为空。用网络禁用测试、错误来源/口令/私有标记负例、隐藏答案检查和原 12 条兼容测试验证。

整套 64 个答疑轮次最多 192 次模型请求。保留单批 42 次请求、3 元上限；manifest 提供五个建议子集，真实入口支持重复 `--case-id`。本次不执行付费模型请求。

数据、说明、清单、生成脚本与离线验证记录纳入 `docs/evals/`，可运行 JSONL 同步到 Python 包。先校验新旧评测，再运行完整后端测试及 20 条内置回归，然后提交并同步 GitHub。长期记忆模块的并行改动保留在原工作区，不混入此提交。

限制：这是包含已用于修订提示的旧条目的开发集，且新增任务复用既有契约；它扩大事实与决策覆盖，不等同于独立留出集、重复可靠性实验或真实学生学习效果研究。
