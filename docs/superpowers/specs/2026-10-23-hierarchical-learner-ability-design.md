# EduAgent 分层学习者能力画像设计

> 历史设计快照，归档日期：2026-11-02。下文保留 2026-10-23 的方案与当时状态。
> 归档不表示分层能力模型、难度适配和画像迁移已实现或验收；
> 当前能力边界以 [面试证据索引](../../engineering/interview-readiness.md)为准。

日期：2026-10-23
状态：设计已确认，待书面规格复核

## 1. 问题事实

当前 `LearnerModel` 只维护“学生 × 知识点”的 BKT 状态。所有学生首次接触所有知识点时均使用 `p_init=0.1`；已有的 `get_overall_progress()` 只是对已接触知识点求平均，用于结果展示，不会影响新知识点初始化、题目难度或学习路径。

因此当前存在三个问题：

1. 不同学生首次接触新知识点时使用相同先验。
2. 已积累的跨知识点表现没有形成稳定、带置信度的能力判断。
3. 前端固定请求 `difficulty=0.5`，本地题库随机抽题后再写入该值，不能声称题目难度已被真实使用或标定。

## 2. 目标与非目标

### 目标

- 从正常独立作答中形成整体及领域能力画像，不增加入学测验。
- 画像用于新知识点先验、题目难度和候选学习路径。
- 保留当前知识点 BKT，避免整体能力覆盖具体知识证据。
- 对能力估计保留证据量、置信度、版本和来源范围。
- 对旧学生从现有知识状态重算，不伪造历史证据。

### 非目标

- 第一阶段不向学生展示整体能力分数。
- 不把耗时、自报信心、对话表达或受助作答直接计入能力。
- 不引入 DKT、IRT 或模型评审。
- 不把命题难度描述为经过心理测量标定的题目参数。
- 不绕过知识图谱前置条件。

## 3. 方案选择

采用三层分层模型：

1. **整体能力基线**：跨领域、变化最慢，仅提供小幅迁移。
2. **领域能力画像**：词汇、语法、阅读、写作、听力、口语、发音分别估计。
3. **知识点掌握度**：保留现有 BKT，变化最快，是具体教学决策的主要依据。

不采用单一综合分，因为它会把不同能力混合；不采用 IRT/DKT，因为当前题量、作答量和题目标定不足。

## 4. 数据模型

新增只读结果模型：

```text
AbilityEstimate
  value               0..1 的收缩估计
  confidence          0..1
  evidence_count      有效知识点或独立证据数
  updated_at

AbilityProfile
  schema_version
  overall             AbilityEstimate
  domains             map[domain, AbilityEstimate]
  source_state_hash   参与计算的知识状态摘要
```

`AbilityProfile` 是由知识状态派生的能力先验，不是第二套权威学习状态。快照可持久化，但失效后必须能够重算。

`KnowledgeNode` 增加显式 `domain: str | None`。英语节点使用七个领域；未知领域节点只能使用整体先验。领域不通过知识点 ID 前缀推断。

## 5. 能力聚合

### 5.1 有效证据

现有 Harness 已确保只有首次、未提示、未查看答案的独立作答更新 BKT。能力聚合只读取这些更新后的知识状态，因此不会再次消费受助、重试或答案揭示行为。

知识点对领域画像的权重由其 `confidence` 决定。证据少的知识点被强烈收缩到默认先验，不能通过一次答对产生高能力判断。

### 5.2 领域与整体估计

领域估计为该领域已接触知识点 mastery 的置信度加权均值，并向默认先验收缩。整体估计由各领域估计再次按领域置信度加权并收缩。

单一领域不能强力决定整体能力：领域覆盖不足时，整体迁移权重保持较低。估计结果记录参与的知识点数和领域数。

第一版使用透明、确定性的聚合公式；所有权重和阈值集中配置，并通过回归样例固定。不得让 LLM 生成或修改能力数值。

## 6. 新知识点初始化

读取知识状态与创建知识状态必须分离：

- `find_state(knowledge_id)`：只读，不存在时返回空。
- `ensure_state(knowledge_id, domain, ability_profile)`：唯一创建入口。

新知识点先验：

```text
overall_weight <= 0.15，由整体置信度控制
domain_weight  <= 0.35，由领域置信度控制
default_weight = 1 - overall_weight - domain_weight

p_init = default * default_weight
       + overall.value * overall_weight
       + domain.value * domain_weight
```

最终结果限制在 `0.10–0.45`。无证据时严格回退 `0.1`。已有知识点不重新初始化，能力画像变化不得改写其 mastery、alpha、beta 或历史计数。

## 7. 难度与学习路径

### 7.1 题目难度

本地题库每题增加 `nominal_difficulty` 和难度等级。它表示命题者给出的相对等级，不是 IRT 标定值。

正常练习由服务端根据以下信息计算推荐难度：

- 当前知识点 mastery 和 confidence；
- 对应领域能力及 confidence；
- 最近独立表现；
- 练习模式。

目标是选择“当前水平附近、略有挑战”的题目。题库没有精确匹配时选择最近等级；连续一次答对不能立即跨越多个等级。

前端不再固定发送 `0.5`。API 难度参数改为可选；教师或诊断场景显式指定时，结果记录 `difficulty_source=manual`，正常自适应记录 `adaptive`。

### 7.2 学习路径

能力画像只在已满足前置条件的候选集合中参与排序：

- 低置信度时优先基础、短路径和更多诊断性练习；
- 同领域能力较高时可优先较有挑战的就绪节点；
- 不得仅凭整体能力将未学知识点判为 mastered；
- 不得跳过知识图谱 prerequisites。

## 8. 组件边界

新增 `AbilityEstimator`，作为纯确定性领域服务：

- 输入：知识状态、知识图谱领域元数据、配置；
- 输出：`AbilityProfile`；
- 不访问数据库、不调用模型、不修改知识状态。

`LearnerModel` 负责知识状态和统一创建入口；`AssessmentAgent` 继续负责独立作答后的 BKT 更新；`CurriculumAgent` 消费画像进行候选排序；`LearningHarness` 保存画像快照及初始化依据。

不新增 Ability Agent，避免为了派生计算引入新的事件和状态所有者。

## 9. 持久化与迁移

Harness checkpoint 增加：

```text
ability_profile
ability_profile_schema_version
ability_source_state_hash
```

恢复时：

1. 快照版本与状态摘要匹配则复用。
2. 版本不支持、摘要不匹配或内容损坏时重算。
3. 旧 checkpoint 没有画像时从已有知识状态重算。

新建知识点的初始化记录包含默认值、整体贡献、领域贡献、最终先验和画像版本，便于 trace 解释。公开 API 不暴露原始内部权重，第一阶段也不向学生展示能力标签。

## 10. 错误处理

- 无有效证据：使用默认先验。
- 只有单领域证据：限制整体置信度和迁移权重。
- 知识点无领域：忽略领域贡献。
- 画像值非有限数或越界：拒绝快照并重算。
- 题库无匹配难度：选择最近可用题，并记录降级原因。
- 显式人工难度越界：返回 422，不静默截断。
- 能力估计失败不能阻断答题提交；回退默认先验并写诊断步骤。

## 11. 测试

### 单元测试

- 无证据时先验为 `0.1`。
- 整体和领域权重随置信度增长但不超过上限。
- 初始化结果始终在 `0.10–0.45`。
- 单一领域不能强力影响其他领域。
- 已存在知识状态不会重新初始化。
- profile hash、版本和重算稳定。

### 集成测试

- 两个独立表现不同的学生获得不同的新知识点先验。
- 同领域迁移大于跨领域迁移。
- 提示、重试、答案揭示不改变画像事实源。
- checkpoint 重启前后画像和初始化一致。
- 旧 checkpoint 可无损恢复并生成画像。
- 自适应难度选择符合题库等级；人工覆盖被记录。
- Curriculum 仍严格遵守 prerequisites。

### 回归验证

- 现有后端全量测试；
- Harness 20 条离线评测；
- 新增能力与难度回归集；
- editable install、wheel 安装和前端构建。

## 12. 实施顺序

1. 增加领域元数据、能力模型和纯聚合器。
2. 拆分知识状态读取与创建，接入个体化先验。
3. 增加画像快照、初始化 trace 和兼容恢复。
4. 为题库增加命题难度并实现服务端自适应选择。
5. 将画像接入 Curriculum 候选排序。
6. 移除前端固定 `difficulty=0.5`，保留可选人工覆盖。
7. 增加单元、集成及离线评测并执行全量验证。

## 13. 验收标准

1. 新学生无证据时行为与当前默认先验一致。
2. 不同学生在足够独立证据后，新知识点先验不同。
3. 同领域迁移明显但受限，跨领域迁移更小。
4. 受助行为不影响整体或领域能力。
5. 已有知识点 mastery 不受画像重算影响。
6. 正常练习难度由服务端决定，不再固定为 `0.5`。
7. 旧 checkpoint 可兼容恢复。
8. 全量测试、离线评测、包构建和前端构建通过。
