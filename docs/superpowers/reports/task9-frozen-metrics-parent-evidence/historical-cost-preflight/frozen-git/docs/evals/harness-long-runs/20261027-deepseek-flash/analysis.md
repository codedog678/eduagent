## 后续修复判断

本轮证据支持继续做局部工程修复，尚不足以证明长任务已可用；这些是建议，不属于本轮实施范围。

1. **先明确结果口径与失败原因。** 下轮冻结前让 L02 评分同时检查业务 outcome/可执行方案；细化 `expert_result_invalid` 的公开错误字段。当前仅保留 ValueError 类型，专家最终 JSON 未留存，无法确定是 task_id、来源引用还是动作一致性校验失败。
2. **处理规划与已有证据的冲突。** L01、L04 的回退和 L01 的重规划拒绝保留了 planner_evidence_conflict；逐项定位规划器输出与已存偏好/目标契约，不放松来源和状态校验。
3. **检索失败及澄清策略按实际资料调整。** L01 的“时态 错误 tense”与“grammar_tenses”搜索为空；L03 在查库前索要已有历史。应先查可访问记录，再基于真实缺口澄清，避免把可选时长作为诊断前置条件。
4. **在现有预算内优化动作与读取顺序。** L06 先用了知识上下文、学习者画像和搜索，第四次工具额度只能读取一条；优先完成必要来源读取。L04 应检查拟备知识点和可学性，再进入动作执行。

L04 的代码确有备题前置知识门禁，略读依赖 `vocab_basic` 和 `grammar_tenses`。但此次 Trace 未保留动作参数及被折叠的 HTTP detail，`unavailable_or_not_allowed` 同时可能表示权限或资源不可用，不能断言此次失败的具体原因就是前置知识不足。
