## Delivered Surface

Exactly four new GET routes reuse the existing Ops bearer/loopback dependency:

| Route | Meaningful Filters |
| --- | --- |
| `/ops/policies/deployments` | environment, state |
| `/ops/policies/deployments/{deployment_id}` | No query parameters |
| `/ops/policies/health-windows` | environment, deployment_id, decision |
| `/ops/policies/audit` | environment, deployment_id, event_type |

List routes use descending `(created_at, typed_id)` keysets, bounded cursor
encoding, `limit=1..100`, exact parameter allowlists and duplicate rejection.
Invalid inputs get non-echoing 422 responses; missing details get 404.
Database/projection failures get a generic 503. No mutation routes were added.
The date-overflow cases at years 0001/9999 now also return safe 422.

All new query methods are inside `OpsQueries`. They explicitly open
`REPEATABLE READ READ ONLY` transactions. Tests inspect PostgreSQL's
`transaction_read_only`, reject real DELETE execution and tripwire command
services; they also assert the HTTP method boundary.

Frozen contracts expose typed deployment/version/head/cohort counts, frozen
thresholds, exact-bound latest gate receipts, latest candidate/stable metrics,
closed audit/threshold labels and timestamps. Lists truncate policy hashes to
12 hex characters; details and Run bindings retain all 64.

Actors, issuers and reasons are opaque `redacted` labels, regardless of stored
text. Freeform details, components, prompts, outputs, salt, nonce, learner IDs,
request IDs and raw namespaces never enter the new projections. Aggregate
fields are individually validated numeric allowlists, not keyword sanitization;
unknown/invalid values remain null. Audit relations are validated UUID/hash
fields and closed transition states, never details bodies.

Run summary/detail and Trace project the stored immutable deployment ID,
effective hash, cohort and production/rehearsal namespace class. Historical
NULL bindings remain unavailable. PostgreSQL tests advance the head and perform
a real health rollback while checking that prior Run bindings do not change.
Rollback audit records on the new rollback deployment are also discoverable
from the failed deployment, through a typed failed-deployment relation.

The Ant Design Policies view has environment/state filters, cursor pagination,
version selection, full version detail, gates, frozen thresholds, health
comparison and rollback/freeze timelines. Runs and Trace link their binding to
Policies. Loading, empty, retry, auth, filter reset and stale-request behavior
are covered; there are no mutation controls or nested cards.
