# 第2章：技术选型与部署架构

## 2.1 三个服务，各司其职

```
┌─────────────────────────────────────────────────────────┐
│                    Docker Compose                        │
│                                                          │
│  ┌──────────┐     ┌──────────────┐     ┌────────────┐  │
│  │ frontend  │────▶│  python-api  │────▶│  postgres   │  │
│  │  :3000    │     │    :8888     │     │   :5432    │  │
│  │  nginx    │     │   FastAPI    │     │  PostgreSQL │  │
│  └──────────┘     └──────────────┘     └────────────┘  │
│                                                          │
│  用户浏览器 ←→  nginx ←→ FastAPI ←→ 数据库               │
└─────────────────────────────────────────────────────────┘
```

### 服务1：postgres — 数据持久化

```yaml
# docker-compose.yml:7-19
postgres:
  image: postgres:16-alpine    # Alpine镜像，体积小
  environment:
    POSTGRES_DB: edu_agent      # 数据库名
    POSTGRES_USER: postgres     # 用户名
    POSTGRES_PASSWORD: postgres # 密码
  ports:
    - "5432:5432"               # 本地开发可直连
  volumes:
    - pgdata:/var/lib/postgresql/data  # 数据持久化
  healthcheck:                  # 健康检查，确保DB就绪后才启动后端
    test: ["CMD-SHELL", "pg_isready -U postgres"]
    interval: 10s
    timeout: 5s
    retries: 5
```

**为什么用 PostgreSQL？**

- 系统需要存储学习记录、事件日志、Agent状态等结构化数据
- 支持 JSON 字段（`metadata`、`state_data`），灵活存储半结构化数据
- asyncpg 驱动支持异步，与 FastAPI 天然匹配

### 服务2：python-api — 后端核心

```yaml
# docker-compose.yml:21-35
python-api:
  build:
    context: ./python           # 构建上下文
    dockerfile: Dockerfile
  ports:
    - "8888:8888"               # FastAPI 默认端口
  environment:
    - DATABASE_URL=postgresql+asyncpg://postgres:postgres@postgres:5432/edu_agent
    - ANTHROPIC_API_KEY=${ANTHROPIC_API_KEY:-}
    - ANTHROPIC_BASE_URL=${ANTHROPIC_BASE_URL:-https://api.anthropic.com}
    - MODEL_ID=${MODEL_ID:-claude-3-sonnet-20240229}
    - ENABLE_DB_LOGGING=true
  depends_on:
    postgres:
      condition: service_healthy  # 等DB健康后才启动
```

**Dockerfile 内容**（`python/Dockerfile`）：

```dockerfile
FROM python:3.11-slim          # 基础镜像
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
EXPOSE 8888
CMD ["python", "-m", "api.main"]  # 启动入口
```

**关键依赖**（`python/requirements.txt`）：

| 包 | 用途 |
|---|---|
| `fastapi` + `uvicorn` | Web框架 + ASGI服务器 |
| `sqlalchemy` + `asyncpg` | 异步ORM + PostgreSQL驱动 |
| `pydantic` + `pydantic-settings` | 数据验证 + 环境变量管理 |
| `httpx` | 异步HTTP客户端（调LLM API） |
| `anthropic` + `openai` | LLM SDK |
| `websockets` | WebSocket支持 |
| `pytest` + `pytest-asyncio` | 测试框架 |

### 服务3：frontend — 用户界面

```yaml
# docker-compose.yml:37-43
frontend:
  build:
    context: ./frontend
    dockerfile: Dockerfile
  ports:
    - "3000:80"                 # 外部3000 → nginx内部80
  depends_on:
    - python-api
```

**Dockerfile 是两阶段构建**（`frontend/Dockerfile`）：

```dockerfile
# 第一阶段：编译
FROM node:20-alpine AS build
WORKDIR /app
COPY package.json .
RUN npm install              # 安装依赖
COPY . .
RUN npm run build            # tsc + vite build → dist/

# 第二阶段：运行
FROM nginx:alpine
COPY --from=build /app/dist /usr/share/nginx/html   # 只拷贝编译产物
COPY nginx.conf /etc/nginx/conf.d/default.conf      # 配置反向代理
EXPOSE 80
```

**为什么两阶段？** 编译完后只需要 nginx + 静态文件，不需要 node_modules，镜像从 ~200MB 缩到 ~30MB。

## 2.2 网络路由：请求如何到达后端

### 生产环境（Docker Compose）

```nginx
# frontend/nginx.conf

# 1. 前端静态资源
location / {
    root /usr/share/nginx/html;
    try_files $uri $uri/ /index.html;   # SPA路由兜底
}

# 2. API请求 → 转发到python-api
location /api/ {
    proxy_pass http://python-api:8888;  # Docker内部DNS
}

# 3. WebSocket → 转发到python-api
location /ws/ {
    proxy_pass http://python-api:8888;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;  # WebSocket升级
    proxy_set_header Connection "upgrade";
}
```

```
用户浏览器
  │
  ├─ GET /              → nginx → 返回 index.html (React SPA)
  ├─ GET /api/health    → nginx → proxy_pass → python-api:8888
  ├─ POST /api/submit   → nginx → proxy_pass → python-api:8888
  └─ WS /ws/xxx         → nginx → proxy_pass → python-api:8888
```

### 本地开发环境（Vite Dev Server）

```typescript
// frontend/vite.config.ts
export default defineConfig({
  server: {
    port: 3000,
    proxy: {
      '/api': 'http://localhost:8888',           // REST代理
      '/ws': { target: 'ws://localhost:8888', ws: true },  // WebSocket代理
    },
  },
})
```

开发时 Vite 开发服务器在 3000 端口，自动把 `/api` 和 `/ws` 代理到后端 8888。

## 2.3 配置管理：环境变量如何工作

### 配置加载链

```
.env 文件 → pydantic-settings → Settings 对象 → 全局 settings 单例
```

`config/settings.py` 的核心设计：

```python
class Settings(BaseSettings):
    # LLM配置（4个提供商，任选一个）
    anthropic_api_key: str = ""
    openai_api_key: str = ""
    minimax_api_key: str = ""
    deepseek_api_key: str = ""

    # 数据库
    database_url: str = "postgresql+asyncpg://postgres:postgres@localhost:5432/edu_agent"

    # 功能开关
    enable_db_logging: bool = True           # 事件是否写DB
    enable_agent_llm_decisions: bool = False  # Agent是否调LLM
    llm_timeout_seconds: float = 12.0

    model_config = SettingsConfigDict(
        env_file=str(ENV_FILE),    # 自动读取 .env 文件
        extra="ignore",
    )
```

### 自动检测当前LLM提供商

```python
@property
def configured_llm_provider(self) -> str:
    if self.anthropic_api_key: return "anthropic"    # 优先级1
    if self.openai_api_key:    return "openai"       # 优先级2
    if self.minimax_api_key:   return "minimax"      # 优先级3
    if self.deepseek_api_key:  return "deepseek"     # 优先级4
    return "template"                                 # 兜底：模板模式
```

**这就是为什么系统没有API Key也能跑** — 自动降级到 `template_adapter`，用关键词匹配生成中文响应。

### .env 文件实际配置

```bash
# .env（当前项目实际使用的）
ANTHROPIC_API_KEY=sk-xiaomimimo...          # 通过小米mimo网关
ANTHROPIC_BASE_URL=https://token-plan-cn.xiaomimimo.com/anthropic  # 代理地址
MODEL_ID=mimo-v2.5                          # 实际模型
DATABASE_URL=postgresql://...                # 注意：这里缺少 asyncpg 前缀
```

> ⚠️ **已知问题**：`.env` 中 `DATABASE_URL` 用的是 `postgresql://`（同步），而 `docker-compose.yml` 和 `settings.py` 默认用 `postgresql+asyncpg://`（异步）。本地开发时需要确认一致性。

## 2.4 应用启动流程

```
python -m api.main
    │
    ▼
FastAPI app 创建 (app = FastAPI(...))
    │
    ├── 注册中间件 CORS (allow_origins=["*"])
    ├── 注册路由 router (legacy /api/*)
    ├── 注册路由 ws_router (/ws/*)
    └── 注册路由 api_router (v1 /api/*)
    │
    ▼
lifespan 启动（应用生命周期）
    │
    ├── 1. 创建 AgentOrchestrator
    │      └── 内部创建 4个Agent + 共享 EventBus
    ├── 2. 初始化数据库 (create_all 建表)
    ├── 3. 检测LLM状态并打印日志
    └── 4. 就绪，等待请求
    │
    ▼
uvicorn 监听 0.0.0.0:8888
```

关键代码在 `api/main.py:34-58`：

```python
@asynccontextmanager
async def lifespan(app: FastAPI):
    global orchestrator
    orchestrator = AgentOrchestrator(enable_db_logging=settings.enable_db_logging)
    app.state.orchestrator = orchestrator
    await orchestrator.init_database()      # 建表
    llm_info = get_llm_service().runtime_info()
    logging.info("LLM status: %s", llm_info)
    yield                                   # 应用运行中
    await orchestrator.close_database()     # 清理
```

## 2.5 技术选型决策总结

| 决策 | 选择 | 理由 |
|---|---|---|
| **后端框架** | FastAPI | 原生async、自动生成OpenAPI文档、Pydantic集成 |
| **ORM** | SQLAlchemy 2.0 async | 异步支持、成熟生态、与asyncpg配合 |
| **数据库** | PostgreSQL 16 | JSON字段支持、可靠性、asyncpg驱动 |
| **前端框架** | React 18 + TypeScript | 组件化、类型安全、生态丰富 |
| **构建工具** | Vite | 开发热更新快、生产构建优化 |
| **反向代理** | nginx | 轻量、SPA支持、WebSocket代理 |
| **容器化** | Docker Compose | 一键部署、环境一致性 |
| **LLM对接** | httpx + 适配器模式 | 不绑定SDK、支持自定义网关 |
| **配置管理** | pydantic-settings | 类型安全、自动读.env、IDE补全 |

## 2.6 汇报要点

**讲这部分时可以这样说**：

> "系统采用经典的三层架构部署：**前端React SPA** → **nginx反向代理** → **FastAPI后端** → **PostgreSQL数据库**，全部通过 Docker Compose 编排。
>
> 技术选型上有两个关键设计：
> 1. **LLM多提供商适配**：通过工厂模式支持 Anthropic/OpenAI/MiniMax/DeepSeek 四种模型，无API Key时自动降级到本地模板响应，确保系统始终可用；
> 2. **异步全链路**：从 FastAPI 到 SQLAlchemy 再到 asyncpg，全链路异步，能高效处理 Agent 并发事件。"
